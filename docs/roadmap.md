# Roadmap / 路线图

[English home](../README.md) · [中文首页](../README.zh-CN.md)

Status as of 2026-09-16. The project is in mechanical prototyping and hardware/software integration. The repository includes reference-gait CSV data and a MATLAB player, plus a four-part standing calibration fixture with an H2D PLA project. Six trained policies — standing against pushes, knock-down recovery, get-up, walking, 1 cm rough terrain, and sit/stand — have been measured in simulation, and those results are now summarised in [measured capabilities](capabilities.md). They are simulation measurements only, and the policies, checkpoints, and measurement tools remain outside this repository. / 截至 2026-09-16，项目处于结构打样和软硬件联合调试阶段；仓库已包含参考步态 CSV 与 MATLAB 回放器，并整理了四件式站姿标定工装及 H2D PLA 工程。六项训练能力（站立抗扰、推倒恢复、起身、行走、1 cm 越障、坐／站）已在仿真里实测，结果汇总在[实测能力清单](capabilities.zh-CN.md)。这些**只是仿真实测**，策略、检查点与测量工具仍不在本仓库。

The table below tracks **public repository deliverables**, not all development work. Simulation code, policy files, and integration evidence will be added as the project progresses. These are deliverables and acceptance criteria, not promised release dates. / 下表跟踪的是**公开仓库交付内容**，不代表项目全部研发工作的状态。仿真代码、策略文件及联调记录将随着项目进展逐步补充，以下目标与验收条件不代表发布日期承诺。

## Known gaps, as measured / 已知不足（已实测）

These are the defects that the 2026-09-16 measurements actually found. They are listed so that the capability summary is not read as a finished result. / 以下是 2026-09-16 那批实测**真正量到**的不足，列在这里是为了不让能力清单被读成"已经做完"。

- **Walking:** side-stepping is unusable (commanded +0.30 m/s produced +0.218 m/s with **+520.4 deg** of uncommanded yaw), in-place turning does not happen (**+0.3 deg** in 10 s), and walk-and-turn reaches only 7 % of the commanded yaw. The shipped checkpoint was trained under a different command range, so it is not directly comparable with the newest table. Retraining is in progress. / **行走：** 侧移不可用（指令 +0.30 m/s，实测 +0.218 m/s，同时出现 **+520.4°** 的未指令自转）；原地转不发生（10 s 转了 **+0.3°**）；边走边转的偏航只有 7 %。已 SHIP 的检查点训练时用的是另一套命令范围，与最新那张表不能直接比较。正在重训。
- **Get-up:** the strict "back to the saved nominal pose" criterion used to be **0/64** with the blocking joint `head_pitch` at **46 deg**, and "did not fall again after standing up" was **4/5**. Both were fixed on 2026-09-16 by `getup_v20`: the strict criterion is now **63/64 (98.4 %)**, the largest joint deviation is **10.4 deg** instead of **52.3 deg**, and the hand-over is **5/5** with **5/5** "did not fall again". The stricter six-axis criterion — which also requires the head off the ground and flat soles, each sustained — stands at **45/64**, up from **0/64**, so that one is still short of the **≥58/64** target. / **起身：** "回到保存的标称姿态"这条严格口径曾经是 **0/64**（卡在 `head_pitch` **46°**），"起身后没有再次摔倒"是 **4/5**。两条都已在 2026-09-16 由 `getup_v20` 修好：严格口径 **63/64（98.4 %）**、最大关节偏差由 **52.3°** 降到 **10.4°**、接力 **5/5** 且"没有再次摔倒"**5/5**。更严的六轴口径（另要求头不压地、脚掌平贴且各自持续成立）是 **45/64**（由 **0/64** 升上来），离 **≥58/64** 的目标仍有差距。
- **Rough terrain:** mean speed is only **61 %** of the command, and no flat-ground control run was made in the same batch, so the loss cannot yet be attributed to the terrain alone. / **越障：** 平均速度只有**指令的 61 %**，且同批没有跑平地对照，因此还不能把掉速单独归因给地形。
- **Sit / stand:** the two reported issues (buzzing in place while standing, and a sitting pose that was neither upright nor left/right symmetric) were measured on CPU and then fixed on 2026-09-16 by `sit_stand_v3`: jitter **0.699 → 0.000**, drift **+27.99 → +0.394 mm/s**, sitting tilt **10.05° → 0.225°**, left/right residual **146.09° → 0.473°**. One limitation arrived with it: the seated pose is not a stance the walking policy can start from (switching to `walk` while seated collapses the robot), so stand up with `m` first. / **坐／站：** 两个被报告的问题（站立时原地抖动、坐姿既不直立也不左右对称）先在 CPU 上实测，随后于 2026-09-16 由 `sit_stand_v3` 修好：抖动 **0.699 → 0.000**、漂移 **+27.99 → +0.394 mm/s**、坐姿倾角 **10.05° → 0.225°**、左右残差 **146.09° → 0.473°**。随之而来一条限制：坐姿不是行走策略起得来的站姿（坐着切到 `walk` 会瘫倒），先按 `m` 站起来。
- **Model gap:** the training model carries measured-mass updates that are not in the published URDF. The head chain is 1.654 kg = 44.1 % of the published model's 3.751 kg, and its worst-case static gravity torque recomputes to 1.574 N·m on the published model versus 1.61 N·m on the training model. / **模型差异：** 训练模型带着尚未公开的实测质量更新。公开模型上头链占 1.654 kg／整机 3.751 kg = 44.1 %，最坏角度下的静态重力矩在公开模型上重算为 1.574 N·m，而训练模型上是 1.61 N·m。
- **No hardware validation:** every number in the capability summary is simulated. Nothing on this page has been confirmed on the physical robot. / **没有实机验证：** 能力清单里的每个数字都是仿真结果，本仓库没有任何一条已在实物上确认。

## Planned: what the beak is for / 计划中：嘴部用来做什么

**Status: planned, not implemented.** Nothing in this section works today, and no date is promised for it. The beak is bus ID 15 on the neck-and-head CAN-FD bus, and it is the reason there are 15 motors on the bus but only 14 values in a policy's action vector: it is a spare independent degree of freedom held back for human-robot interaction, so no published policy drives it. The bus IDs themselves are in [the bus ID notes](../hardware/motor_ids.md) / [中文总线 ID 说明](../hardware/motor_ids.zh-CN.md). / **状态：计划中，未实现。** 本节所述目前一项都不能用，也没有承诺任何日期。嘴部是脖子及头部总线上的总线 ID 15，它也正是"总线上有 15 个电机、而策略动作向量只有 14 个值"的原因：它是一个被留给人机交互的独立自由度，因此没有任何公开策略驱动它。总线 ID 本身见[总线 ID 说明](../hardware/motor_ids.zh-CN.md)／[英文](../hardware/motor_ids.md)。

The two planned uses below are the maintainer's stated plan. / 下面两项计划用途是维护者口述的计划。

- **Planned use 1 — sound feedback.** Close and open the beak in response to a human voice; a module with speech recognition is to be added later. / **计划用途 1 —— 声音反馈。** 听到人声后做张合嘴的反馈；后续会接一个带语音识别功能的模块。
- **Planned use 2 — holding a small ball.** Grip and hold a small ball in the cavity of the mouth, together with the on-board binocular structured-light depth camera. / **计划用途 2 —— 含住小球。** 用嘴里的空腔夹住并含住小球，结合机上的双目结构光深度相机。

What the model has today, written out so that "planned" is not read as "supported": / 模型今天的实际情况 —— 写在这里，是为了不让"计划中"被读成"已支持"：

- `mouth` is **one revolute joint**, with `head_roll_link` as its parent, axis `0 1 0`, and a range of 0 to 102.5 degrees in [joint_limits.csv](../models/wmduck/joint_limits.csv). One degree of freedom can bite and hold by cavity, but it cannot pinch. / `mouth` 是**单个转动关节**，父 link 为 `head_roll_link`，轴向 `0 1 0`，在 [joint_limits.csv](../models/wmduck/joint_limits.csv) 里范围是 0 到 102.5 度。单自由度能"咬合 + 靠空腔含住"，但做不了捏取。
- **The simulation the policies are published and trained in has no cavity in the mouth.** In [robot_walk.xml](../models/wmduck/mjcf/robot_walk.xml) — standing, sit/stand, walking, and rough terrain — the **entire head chain has no collision geometry at all**. In [robot_groundcontact.xml](../models/wmduck/mjcf/robot_groundcontact.xml) — get-up — the mouth is approximated by **one solid box**, `<geom name="mouth_link_box0_collision" type="box" size="0.051375 0.041883 0.016277"/>`; a MuJoCo box `size` is a half-extent, so that box measures about 0.103 × 0.084 × 0.033 m and it has no cavity. In the URDF, by contrast, `mouth_link`'s collision is the `Mouth.stl` mesh itself, so the CAD cavity is kept there. / **公开策略训练与运行所用的仿真里，嘴里没有空腔。** 在 [robot_walk.xml](../models/wmduck/mjcf/robot_walk.xml)（站立、坐站、行走、越障）里**整个头链没有任何碰撞体**；在 [robot_groundcontact.xml](../models/wmduck/mjcf/robot_groundcontact.xml)（起身）里，嘴被近似为**一个实心盒** `<geom name="mouth_link_box0_collision" type="box" size="0.051375 0.041883 0.016277"/>` —— MuJoCo 盒体的 `size` 是半边长，因此该盒约 0.103 × 0.084 × 0.033 m，而且没有空腔。而在 URDF 里，`mouth_link` 的碰撞体**就是 `Mouth.stl` 网格本身**，CAD 空腔在 URDF 里保留了。
- **So simulating "holding a ball" has to be built separately.** It needs a collision representation of the cavity, a free ball rigid body, and friction and contact tuning, with the stability of concave-body and mesh contact verified on its own. / **因此"含住球"的仿真必须另做。** 需要给空腔一个碰撞表示、加一个自由小球刚体、并调摩擦与接触参数，还要单独验证凹体与网格接触的稳定性。
- **No model contains a camera.** `camera`, `depth`, and `stereo` appear nowhere in the URDF or in either MJCF, and this repository makes no perception claim anywhere. The depth-camera plan therefore has no representation in the simulation or in a perception chain yet: it is a new subsystem. / **模型里没有任何相机。** `camera`、`depth`、`stereo` 在 URDF 与两个 MJCF 里都不出现，本仓库任何地方也没有做感知声称。因此深度相机方案目前在仿真与感知链路里都没有表示，属于新子系统。
- **Whether the beak can hold a ball is a question of geometry and friction, not of torque.** The beak uses the same motor as the other 14: 15 instances of the same HTDW3532 specification, rated 0.6 N·m. / **含球的成败取决于几何与摩擦，不是扭矩。** 嘴部电机与其余 14 个相同：15 个实例同为 HTDW3532、额定 0.6 N·m。

## Suggested milestones / 建议阶段

1. **Mechanical reference package / 机械参考资料包** — this package, followed by independent CAD opening checks. / 当前资料包，随后完成独立 CAD 打开检查。
2. **Reproducible physical build / 可复现的实物搭建** — complete the BOM, manufacturing, assembly, and electrical documentation together. / 配套补齐 BOM、制造、装配及电气文档。
3. **Measured robot model and reproducible simulation / 经实测修正的模型与可复现仿真** — reconcile the model with hardware measurements and publish the simulation environment and validation. / 用实测数据校准模型，公开仿真环境及验证记录。
4. **Reproducible motion / 可复现的运动控制** — publish control or training software with hardware versions and test conditions, together with the measurement tools behind the [capability summary](capabilities.md). / 发布控制或训练软件，记录硬件版本与测试条件，并公开[能力清单](capabilities.zh-CN.md)背后的测量工具。

Document new claims together with their evidence. A successful model import establishes that the file can be compiled; it does not establish walking performance or hardware reproducibility. Simulation measurements establish what a policy did in one environment on one date; they do not establish what the physical robot will do. / 新增结论应附带对应证据。模型成功导入只证明文件可编译，不代表行走性能或实物复现已经验证；仿真实测只说明某个策略在某一天、某个环境里的表现，不代表实物会同样表现。
